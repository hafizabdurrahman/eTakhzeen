You have eTakhzeenContactTableId (user messages) and eTakhzeenResponseTable (admin replies) — keep both, but add one more: a Conversations table. This is what makes unread badges, department routing, and inbox sorting actually work without expensive queries.

1. Conversations table (new — add an env var like ETAKHZEEN_CONVERSATION_TABLE_ID)

This is the "thread" — one row per user-department conversation.

Column	Type	Notes
userId	string, required, indexed	Appwrite user ID
userName	string	denormalized for fast inbox rendering
userEmail	string	optional
department	enum: admin, manager, support, other	this is your "label" selector
productId	string, optional	if inquiry is about a specific product
productName	string, optional	denormalized
subject	string, optional	short topic line, e.g. auto-filled from first quick question
status	enum: open, pending, resolved, closed	default open
lastMessage	string	preview text for inbox list
lastMessageAt	datetime, indexed	for sorting inbox by recency
lastSenderRole	enum: user, admin	who sent the last message
unreadByAdmin	integer, default 0	badge count on admin side
unreadByUser	integer, default 0	badge count on user side
assignedAdminId	string, optional	if you want specific staff ownership

Index: userId, department, status, lastMessageAt.

2. Contact table (eTakhzeenContactTableId) — messages from the user
Column	Type	Notes
conversationId	string, required, indexed	links to Conversations
userId	string, required	
content	string, required	the message text
type	enum: text, quick_question	quick_question = selected from prebuilt list
quickQuestionId	string, optional	ref to FAQ table below
attachments	string[], optional	file IDs from your bucket
isRead	boolean, default false	read by admin
$createdAt	(built-in)	Appwrite gives you this automatically
3. Response table (eTakhzeenResponseTable) — messages from admin
Column	Type	Notes
conversationId	string, required, indexed

Column	Type	Notes

How the flow works

On /contact page (user side):

User picks a department (Admin / Manager / Support / Other) — this is a simple button/tab group, not a text field.
Optionally picks a product from a dropdown.
Query Conversations for userId == currentUser && department == selected. If one exists and is open/pending, load it. If not, create a new row.
Show relevant quick questions for that department/product from the FAQ table as tappable chips. Tapping one:
Creates a message in the Contact table with type: quick_question
Optionally auto-inserts the matching answer as an instant system/admin-style reply into the Response table (feels like a bot answering instantly)
Load messages: query Contact table by conversationId + query Response table by conversationId, merge both arrays and sort by $createdAt client-side, render as chat bubbles (role tags which side they render on).
On send: insert into Contact table → update the Conversation row (lastMessage, lastMessageAt, lastSenderRole: "user", unreadByAdmin += 1, unreadByUser: 0).

Admin panel:

Inbox = query Conversations ordered by lastMessageAt desc, with tabs/filters by department and status. Show unreadByAdmin as a badge.
Opening a thread: merge-sort Contact + Response messages same as above, then reset unreadByAdmin: 0 on that conversation.
Replying: insert into Response table → update conversation (lastMessage, lastSenderRole: "admin", unreadByUser += 1, unreadByAdmin: 0).

Unread badge for the user (e.g. a chat icon in your navbar): sum unreadByUser across all their conversations.

Realtime: subscribe to both the Contact and Response tables filtered on conversationId for a live thread, and subscribe to the Conversations table (filtered by userId for the user, or unfiltered/by department for admin) to keep unread badges live without polling.

Permissions: on the Contact/Conversations rows, give Permission.read/write(Role.user(userId)) to the owner, and Role.team("admins") (or a label like Role.label("admin")) read/write access to everything — that's how you gate the admin panel.
